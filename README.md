# ExtBlocks (External Blocks)

  For SillyTavern 1.14.0+ (staging)

	This extension allows for the external generation of content blocks.

- **Repository**: `https://gitgud.io/Monblant/extblocks`
- **Installation**: `Extensions` → `Install extension` (top right) → Paste repository link.
- **Updating**: `Extensions` → `Manage extensions` (top right) → Scroll down → Click `Update` next to ExtBlocks.

---

# Overview

## Terminology
- **Block**: Any structure enclosed in XML-like tags, e.g., `<block_name>...</block_name>`.
- **Main API**: The API used for generating the main chat response.
- **Secondary API**: A separate API and model used specifically for generating blocks.

## What It Does
- **Automated Block Generation**: Automatically generates blocks based on triggers (user messages and/or character responses) and saves them within the message configuration.
- **Secondary API Support**: Allows using a separate API for block generation with its own dedicated settings.
- **Presets and Editing**: Lets you edit block configurations and create reusable block presets.
- **Character Card Integration**: Allows embedding block configurations directly into character cards.
- **Automatic Regex Creation**: Can automatically generate regular expressions to hide blocks from the main prompt and/or the chat display.
- **Flexible Injection**: Injects blocks at a specified depth relative to user/character messages, or before/after the system prompt.

## Why Use ExtBlocks?
- **Dynamic Content**: Generate dynamic blocks like infoboxes, `thinking` processes, or summaries.
- **Clean Prompts**: Keep your main prompt clean from block-related instructions.
- **Stop String Compatibility**: Works in environments with stop strings (e.g., with the [noass_ext](https://rentry.org/noass_ext) extension).
- **Secondary API Benefits**:
    - Conserve main API key usage.
    - Bypass rate limits.
    - Use faster or more specialized models for block generation.
- **Isolated Generation**: Use separate API settings, system prompts, or prefills for blocks.
- **Guaranteed Periodicity**: Ensure blocks appear at regular intervals.
- **Improved Instruction Following**: Isolated context and prompts lead to better instruction adherence.
- **Better Lorebook Integration**: Separated generation processes work more effectively with lorebooks.

## Block Types

1.  **Generated Block**: A block generated by the secondary API.
2.  **Rewrite Block**: A generated block that rewrites the main character response.
3.  **Accumulative Block**: A block that updates its content based on an "updater" block appearing in the main response.
4.  **Script Block**: A block that executes STScript or JavaScript code. **Warning: Always review JS scripts before execution to ensure they are safe.**

# Configuration

The extension is enabled by toggling the `Enable ExtBlocks` checkbox.

## API Settings

The extension uses its own API settings for block generation, separate from the main chat settings. This allows you to use different models, accounts, or services.

The settings have been migrated to use SillyTavern's **Connection Profiles**. A Connection Profile combines the API source (e.g., OpenAI, Claude), model, and proxy into a single profile. You can manage these in the main `API Settings` panel (the wrench icon).

ExtBlocks provides three configurable **API Presets**: `Big`, `Medium`, and `Small`. Each preset can be configured with its own Connection Profile and generation parameters (temperature, streaming, etc.).

**Configuration Steps:**
1.  **Configure API Presets**: In the `API Settings` section within the ExtBlocks panel, use the dropdown to select and configure each preset (`Big`, `Medium`, `Small`). For each one, choose a **Connection Profile** from your SillyTavern setup and adjust other settings as needed.
2.  **Assign Presets to Blocks**: Each block configuration now includes a preset selector icon (a battery icon). You can click this icon to cycle through and assign one of the three API presets to that specific block.

This system allows for flexible resource management. For example, you can use a powerful model (the `Big` preset) for complex, creative blocks, and a faster, cheaper model (the `Small` preset) for simple, frequent blocks.

# Interaction

## Block Presets and Embedded Blocks

- **Block Presets**: Located at the top under `ExtBlocks Preset`. You can create new presets, import from JSON, export to JSON, and delete them.
- **Preset Blocks**: Below the presets, in the `Preset blocks` section, you can add or import block configurations into the selected preset.
- **Embedded Blocks**: Further down, the `Embedded blocks` section allows you to add or import block configurations directly into a character card. These configurations are stored within the card itself.

## Editing Blocks

In both the `Preset blocks` and `Embedded blocks` tabs, you can perform the following actions on blocks: enable/disable, edit, export to JSON, export the prompt to JSON, and delete.
### Accumulative Blocks
In the edit window, you can set the following for a block:

- **Name**: The exact name of the block without `<` and `>`.
- **Updater Block Name**: The exact name of the updater block without `<` and `>` (must be different from the main block name).
- **Triggers**:
	- `User Message`: The block will be updated based on the user's message.
	- `Char Message`: The block will be updated based on the character's message.
- **State**:
	- `Disabled`: Whether the block (and its generation) is disabled.
	- `Hide From Display`: Whether to hide the block from the user's view.
	- `Inject Block`: Whether to insert the block into the context for the main generation.
  - `Background Generation`: Whether the block should be generated at background.
- **Injection Settings**:
	- `Injection Role`: The role for injection (system, assistant, or user).
	- `Injection Position`:
		- `After Main Prompt` and `Before Main Prompt`: Works correctly only with the system role. The main prompt must be enabled in the preset.
		- `In Chat`: Injects into the chat at a certain depth, works correctly with user and assistant roles.
	- `Injection Depth`: The depth for chat injection. Negative values insert the block from the beginning of the chat, positive values from the end.

	**Example of an accumulative block**
	The lines of an accumulative block must have a constant structure: `Property: Value`.
	The following value types are supported: string (e.g., `Name`), number (e.g., `Gold`), and array (e.g., `Inventory`).
	In an array, lines look like `Item: Item Count` (e.g., `Apple` and `Sword`).
	Note: If there is only one item, you can just write `Item` without a colon and count (e.g., `Map`).
	```
	<example>
	Name: Test
	Gold: 100
	Inventory: [
	  Apple: 4
	  Sword: 2
	  Map
	]
	</example>
	```

	**Example of an updater block**
	The updater block supports several operations: assignment (e.g., `Name`), addition/subtraction for numeric values (e.g., `Gold`), and adding/removing items from an array (e.g., `Inventory`).
	Note the lack of a space after `+` for addition/subtraction, and the presence of a space for adding/removing items.
	```
	<example updater>
	Name: User
	Gold: +5
	Inventory: + Scroll
	Inventory: - Apple
	</example updater>
	```
### Generated Blocks
In the edit window, you can set the following for a block:

- **Name**: The exact name of the block without `<` and `>`.
- **Type**: `Inject` or `Rewrite` (more on this below).
- **Block Template**: The template for the block's structure.
- **Block Prompt**: The instructions for the AI to generate the block's content.
- **Triggers**:
	- `User Message`: The block is generated after a user's message (and also after a swipe if the chat was modified).
	- `Char Message`: The block is generated after a character's message.
	- `Generation Pause`: Pauses the main response generation when a keyword is found. Blocks with this trigger will be generated, and then the main generation will resume. Only supports keyword-based periodicity.
- **Periodicity**: Whether the block is generated at a set interval or based on a keyword.
- **Period**: The interval between message numbers. For example, with the `User message` trigger, a period of 2 generates the block for every user message; a period of 4 generates it for every second user message, etc. Odd periods are only useful if both triggers are enabled.
- **Keyword**: A string that triggers block generation when found in a message.
- **State**:
	- `Disabled`: Whether the block (and its generation) is disabled.
	- `Hide From Display`: Whether to hide the block from the user's view.
	- `Inject block`: Whether to insert the block into the context for the main generation.
- **Injection Settings**:
	- `Injection Role`: The role for injection (system, assistant, or user).
	- `Injection Position`:
		- `After Main Prompt` and `Before Main Prompt`: Works correctly only with the system role. The main prompt must be enabled in the preset.
		- `In Chat`: Injects into the chat at a certain depth, works correctly with user and assistant roles.
	- `Injection Depth`: The depth for chat injection. Negative values insert the block from the beginning of the chat, positive values from the end.
- **Context** (right side of the editor): Additional information for generation. Several context types are available:
	- `Text`: Free text, supports Tavern macros.
	- `Last messages`: Recent messages with optional prefixes/suffixes. A negative `Messages Count` includes the first messages instead.
	- `Last messages by keyword`: Recent messages up to a specific keyword. Useful for keyword-triggered blocks.
	- `Previous block`: The content of the previous instance of this block.
- **Context Order**: Displayed at the bottom right; items can be moved up/down or deleted. Context can be imported and exported. Blocks with the same context and trigger will be generated in a single API call (respecting their period).

	**Example of a correct name-template-prompt combination for a generated block:**
	**Block Name:**
	`current time`
	**Block Template:**
	```
	<current time>
	Time of the day: HH:MM:SS
	</current time>
	```
	**Block prompt:**
	`Write the current time of day in the <current time> block.`

### Rewrite Blocks
A subtype of generated blocks, but instead of being injected, they rewrite the main response. The editor has an additional `Generation Order` parameter to control whether the block rewrites the message before or after other blocks are generated.
The template for rewrite blocks must contain a `<rewritten text>` block; the rest of the content is flexible. The block name can be anything, unlike regular generated blocks.

	**Example of a correct name-template-prompt combination for a rewrite block:**
	**Block Name:**
	`basic rewrite`
	**Block Template:**
	```
	<rewritten text>
	Rewritten text here
	</rewritten text>
	```
	**Block prompt:**
	`Rewrite the given text.`

### Script Blocks
In the edit window, you can set the following for a block:

- **Name**: The exact name of the block without `<` and `>`.
- **Script Type**: `STScript` or `JS`.
- **Script Text**: The code to be executed.
- **Triggers, Periodicity, State**: Same as for generated blocks.
- **Execution Order**: Whether the script runs before or after block generation.
#### API for JS Scripts

##### **Working with STScript:**
- `(async) executeST(text)`: Executes an STScript string passed to the function.

##### **Getting Blocks:**
- `getAllBlocks()`: Retrieves all blocks from the current preset and character card as an array.
- `getAllGeneratedBlocks()`: Retrieves all generated blocks.
- `getAllRewriteBlocks()`: Retrieves all rewrite blocks.
- `getAllScriptBlocks()`: Retrieves all script blocks.
- `getAllEnabledBlocks()`: Retrieves all enabled blocks.
- `getPreviousBlockContextUnconditional(block, messageId, may_current, count)`: Gets previous states of a block.
  - `block`: The block object to get states for.
  - `messageId`: The starting message ID to search from.
  - `may_current` (optional, boolean, default: `false`): Whether to search for the block in the message with `messageId`.
  - `count` (optional, number, default: 1): The number of previous states to retrieve.

##### **Working with Blocks:**
- `(async) generateRewrite(rewriteBlock, messageId, allBlocks, additionalMacro)`: Generates a rewrite block, returning a string.
  - `rewriteBlock`: The rewrite block object.
  - `messageId`: The message ID for which the block is generated.
  - `allBlocks`: An array of all relevant blocks.
  - `additionalMacro` (optional): An object for additional macros, e.g., `{ fruit: 'apple' }` allows using `{{fruit}}`.

- `(async) handleRewriteBlocks(rewriteBlocks, generation_order, messageId, allBlocks, additionalMacro)`: Generates rewrite blocks and rewrites the specified message.
  - `rewriteBlocks`: An array of rewrite blocks.
  - `generation_order`: Filters blocks by whether they generate `'before'` or `'after'` the main blocks.
  - `messageId`, `allBlocks`, `additionalMacro`: Same as above.

- `(async) handleScriptBlocks(scriptBlocks, execution_order)`: Executes script blocks.
  - `scriptBlocks`: An array of script blocks.
  - `execution_order`: Filters scripts by whether they execute `'before'` or `'after'` the main blocks.

- `(async) generateBlockContent(blocksInGroup, messageId, allBlocks, additionalMacro)`: Generates blocks, returning a string.
  - `blocksInGroup`: An array of generated blocks with the same context (usually an array with one block).
  - `messageId`, `allBlocks`, `additionalMacro`: Same as above.

- `(async) handleGeneration(generatedBlocks, messageId, allBlocks, additionalMacro, is_separate)`: Generates blocks and inserts them into a message.
  - `generatedBlocks`: An array of generated blocks.
  - `is_separate` (optional, boolean, default: `false`): If `true`, blocks are placed in a new system message instead of the message with `messageId`.
  - `messageId`, `allBlocks`, `additionalMacro`: Same as above.

- `(async) handleBlocksGeneration(messageId, isUser, allBlocks, triggeredBlocks, additionalMacro, is_separate)`: Handles the processing and generation of all blocks for a given message.
  - `isUser` (boolean): Whether the message is from the user.
  - `triggeredBlocks`: An array of blocks to be processed.
  - `messageId`, `allBlocks`, `additionalMacro`, `is_separate`: Same as above.

- `injectBlock(block, blockConfig)`: Injects a block's state into the main context.
  - `block` (string): The block's state.
  - `blockConfig` (object): The block's configuration.

##### **Extension Context:**
- `extStates`: A constant object holding the extension's states.
  - `ExtBlocks_settings`: The extension's settings.
  - `current_set`: The current block preset.
  - `api_preset`: The current API preset.
  - `spoilerRegex`, `self_reload_flag`, `is_chat_modified`: Internal technical values.

##### **Tavern Context:**
- `context`: A constant object holding Tavern's functions and states, defined in `/public/scripts/st-context.js`.

##### **Script Block Examples:**

1)  **Generate and insert a `scene info` block for the last message in the chat:**
    ```javascript
    const messageId = context.chat.length - 1;
    const lastMessage = context.chat[messageId];
    const isUser = lastMessage.is_user;
    const allBlocks = getAllBlocks();
    const triggeredBlocks = allBlocks.filter((e) => e.name === 'scene info');
    await handleBlocksGeneration(messageId, isUser, allBlocks, triggeredBlocks);
    ```

2)  **Generate a `profile` block as a string and log it to the browser console:**
    ```javascript
    const messageId = context.chat.length - 1;
    const allBlocks = getAllBlocks();
    const blocksInGroup =  allBlocks.filter((e) => e.name === 'profile');
    const blockStr = await generateBlockContent(blocksInGroup, messageId, allBlocks);
    console.log(blockStr);
    ```

3)  **Get the four previous states of the `scene info` block and log them:**
    ```javascript
    const messageId = context.chat.length - 1;
    const allBlocks = getAllBlocks();
    const blocks = allBlocks.filter((e) => e.name === 'scene info');
    if (blocks.length === 1) {
        const blockStates = getPreviousBlockContextUnconditional(blocks[0], messageId, true, 4);
        console.log(blockStates);
    }
    ```

4)  **Rewrite the last message using a `basic rewrite` block if it contains trigger words:**
    ```javascript
    const messageId = context.chat.length - 1;
    const lastMessageContent = context.chat[messageId].mes;
    const allBlocks = getAllBlocks();
    const rewriteBlocks = allBlocks.filter((e) => e.name === 'basic rewrite');
    const generation_order = 'before';

    function containsAnyIgnoreCase(str, substrings) {
        return substrings.some(sub => 
            str.toLowerCase().includes(sub.toLowerCase())
        );
    }

    if (containsAnyIgnoreCase(lastMessageContent, ['glint', 'smirk', 'camaraderie'])) {
        await handleRewriteBlocks(rewriteBlocks, generation_order, messageId, allBlocks);
    }
    ```

5)  **Inject the last state of the `scene info` block:**
    ```javascript
    const blockName = 'scene info';
    const messageId = context.chat.length - 1;
    const allBlocks = getAllBlocks();
    const blocks = allBlocks.filter((e) => e.name === blockName);
    if (blocks.length === 1) {
        const blockConfig = blocks[0];
        const blockState = getPreviousBlockContextUnconditional(blockConfig, messageId, true);
        injectBlock(blockState, blockConfig);
    }
    ```

## Block Initialization
You can initialize blocks for new chats by adding them to the greeting (the first message). If you add blocks by editing the first message, you need to reload the chat for the blocks to be moved to the block storage. You can verify that the blocks have been added by editing the message again—they should no longer be visible in the message text.

## Editing Blocks in a Message
Generated blocks are stored within messages and can be edited. Click the three dots on a message, find the pencil-on-paper icon (usually the last button), and click it to open the editor. Edit the blocks and save your changes.

## Slash Commands

-   **/extblocks-generate**: Generates one or more blocks. The command works even if the block is disabled.
    -   `name` (required): The name(s) of the block(s) to generate, separated by commas.
    -   `is_separate` (optional): If `true`, the block will create a new message from the system role.
    -   Unnamed argument: Additional text that can be used as a prompt. Access it in the block's prompt, template, and context via the `{{additionalPrompt}}` local macro.
    
    **Example:**
    `/extblocks-generate name="reflexion, thinking"`

-   **/extblocks-regenerate**: Regenerates the last generated blocks.
-   **/extblocks-flushinjects**: Clears all injected content from ExtBlocks.
-   **/extblocks-storage-append**: Adds a block to the last message's block storage.
    -   Unnamed argument: The block string (replace newlines with `{{newline}}` and `|` with `\|`).
-   **/extblocks-storage-purge**: Clears the last message's block storage.
-   **/extblocks-storage-export**: Exports all previous blocks into a system message (useful for transferring chats).
-   **/extblocks-rewrite**: Triggers rewrite blocks. The command works even if the block is disabled.
    -   `name` (required): The name(s) of the rewrite block(s), separated by commas.
    -   Unnamed argument: Additional prompt text, accessible via the `{{additionalPrompt}}` macro.
-   **/extblocks-execute-script**: Executes script blocks. The command works even if the block is disabled.
    -   `name` (required): The name(s) of the script block(s), separated by commas.

## Macros

### Global Macros

	Macros that can be used anywhere in SillyTavern.
-   `{{ExtBlocks::block_name}}`: Access the last state of a specific block.
-   `{{ExtBlocks-Call::blocks_names::[additional_prompt]}}`: Calls block generation by blocks names, separated by comma. Optionally, you can submit an additional prompt, as in `/extblocks-generate` slash command.
-   `{{ExtBlocks-CallRewrite::blocks_names::[additional_prompt]}}`: Calls message rewrite by blocks names, separated by comma. Optionally, you can submit an additional prompt, as in `/extblocks-rewrite` slash command.
-   `{{ExtBlocks-CallScript::blocks_names}}`: Runs script execution by blocks names, separated by comma.

### Local Macros

	Macros that can only be used in the prompt, template, and context of a generated block.
-   **Lorebook Macros** (only for entries that are always active or activated by the block's context+template+prompt):
    -   `{{wiBefore}}`: Lorebook entries with position `↑Char`.
    -   `{{wiAfter}}`: Lorebook entries with position `↓Char`.
    -   `{{wiExamples}}`: Lorebook entries with position `↑EM` and `↓EM`.
    -   `{{wiDepth}}`: Lorebook entries with position `@D`.
    -   `{{wiAll}}`: All activated lorebook entries.
-   `{{mainPrompt}}`: The main prompt of the current preset.
-   `{{additionalPrompt}}` The additional prompt passed through a slash command.

## Known Issues
-   If you exit the message edit mode by clicking the 'X' button, the blocks may not be displayed. This can be fixed by exiting edit mode using the checkmark button or by reloading the chat.
